# User Personas

**Product:** Resource Organizer

**Version:** 1.0

**Status:** Draft

---

# Purpose

This document defines the primary users of Resource Organizer.

Understanding users helps ensure every product decision solves a real problem instead of adding unnecessary features.

The MVP is designed for individuals who regularly save online resources and struggle to rediscover them later.

---

# Primary Persona

## Developer

### Overview

Developers constantly discover useful resources while learning, building projects, or solving problems. These resources are often spread across multiple platforms, making them difficult to find later.

---

### Profile

- Age: 18–40
- Technical knowledge: High
- Uses desktop daily
- Comfortable with productivity tools
- Frequently learns new technologies

---

### Frequently Used Platforms

- GitHub
- YouTube
- Stack Overflow
- Dev.to
- Medium
- Official Documentation
- Reddit

---

### Goals

- Save useful resources quickly.
- Find previously saved solutions.
- Organize learning materials.
- Reduce duplicate searching.
- Build a long-term knowledge library.

---

### Frustrations

- Too many browser bookmarks.
- Can't remember where a resource was saved.
- Keyword search fails.
- Folder structures become messy.
- Saved resources become forgotten over time.

---

### User Quote

> "I know I've seen this before, but I can't remember where."

---

### Success Criteria

The developer can:

- Save a resource in seconds.
- Search using ideas instead of exact titles.
- Discover related resources.
- Build an organized knowledge library with minimal effort.

# Common User Behaviors

Across all personas, users typically:

- Save resources faster than they revisit them.
- Save from multiple platforms.
- Forget why something was saved.
- Search using concepts instead of titles.
- Prefer simple workflows.
- Avoid manual organization whenever possible.

---

# Jobs To Be Done

Users hire Resource Organizer to:

- Save useful information quickly.
- Find information later.
- Build a searchable knowledge library.
- Reduce duplicate searching.
- Remember why a resource mattered.

# Pain Points Summary

| Problem | Impact |
|---------|--------|
| Too many bookmarks | Hard to navigate |
| Multiple platforms | Information scattered |
| Forgotten resources | Wasted learning |
| Poor search | Time lost |
| Manual folders | High maintenance |

---

# User Needs

Users need:

- Fast saving
- Reliable search
- Minimal manual organization
- Context preservation
- Intelligent recommendations
- Trustworthy AI

---

# Design Implications

These personas influence several product decisions:

- Saving should require minimal effort.
- Search should be available from every screen.
- AI suggestions must always be optional.
- Resources should never disappear into hidden folders.
- Notes and descriptions should preserve personal context.
- The interface should remain simple even as the library grows.

---

# Guiding Principle

Every feature should help users answer one question:

**"Can I quickly find something I know I saved?"**

If the answer is yes, the product is fulfilling its purpose.
